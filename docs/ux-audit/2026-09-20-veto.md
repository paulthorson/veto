## Executive bottom line

Veto’s **LIVE face** (`https://www.vetomcp.com`) is a strong, honest marketing + demo SPA: clear “fill forms, never submit” pitch, working hash routes (`#/docs`, `#/demo`, `#/dashboard`, `#/install`, `#/changelog`), and real `prefers-reduced-motion` kill. It fails Soft primarily on **public GitHub CTAs that 404** (repos private / missing at the advertised URL) and on **faint secondary copy** (`--ink-faint` ~3.8:1).

The **product app face** (local WebUI in this repo: `cli.py serve` → `http://127.0.0.1:8765`) is coherent with the same pixel system and has excellent empty states — but **Soft nav is unpaid**: sidebar routes omit **CORE** and **APPLY** catalog groups, so primary jobs (Job search, Apply queue, Profile wizard, Doctor, Analytics, Application grill) are not first-class destinations. That is the highest-leverage product-app fix.

## Bars

### 1. DESIGN_AGENCY_BAR — **Adequate (leaning Strong on brand; Weak on product IA)**

- **Keep:** Cohesive pixel-arcade system (tokens, hard shadows, square radius, mono UI). Brand “SAYS NO” is hero-level on LIVE. Product empty states read intentional, not abandoned.
- **Miss:** Hero motion competes with brand on LIVE; product IA hides core jobs; phone guide still carries retired rounded corners (`10px` / `999px`) vs token `--radius: 0`.
- **Agency test:** Marketing face would pass a craft critique with polish notes. Product face would not pass an IA critique until CORE/APPLY are navigable.

### 2. UX laws + honesty — **Strong on honesty; Adequate on laws**

- **Honesty Strong:** Live copy owns refusals and limits (“won’t apply while you sleep… won’t get you hired”). Product empty states show real zeros, not vanity seed on local app. Confirm-gated destructive API paths (documented + wizard REVIEW step). Footer asks users to verify postings on live employer sites.
- **Honesty Weak (LIVE):** Primary GitHub / “STAR ON GITHUB” destinations resolve to **404** for anonymous users (`paulthorson/veto` private; advertised `veto-mcp` not found). That oversells “open source you can star/clone now.”
- **UX laws:** Clear hierarchy on both faces; product wizard is stepwise. Failures: orphaned CORE/APPLY; CTA label mismatch (`START` → install, not a start session); demo dashboard on LIVE can be mistaken for the real local product app without a louder “demo / seeded” signal.

### 3. WCAG 2.x AA Soft — **REJECTED (Soft pass REJECTED)**

Measured from shipped LIVE CSS tokens (`--bg #0d1117`, `--muted #7d8590`, `--ink-faint #6f6d84`):

| Pair | Approx contrast | AA normal text (4.5:1) |
|---|---|---|
| `--muted` on `--bg` | **~5.07:1** | Pass |
| `--ink-faint` on `--bg` | **~3.78:1** | **Fail** (used widely for secondary / lede-adjacent chrome on LIVE) |
| Primary green button ink on green | High | Pass |

Observed Soft issues (not a full lab cert):

- **1.4.3 Contrast:** `--ink-faint` fails AA Soft; do not treat muted-only body as “all clear.”
- **2.2.2 Pause/Stop/Hide:** Hero terminal loops; reduced-motion **is** respected on LIVE (DevTools confirmed). Soft still wants a **visible pause** for users who do not set OS preference.
- **2.4.7 Focus:** LIVE nav showed cyan/neon focus; product WebUI showed neon rings on nav + primary buttons. Modal dialog lacks `aria-labelledby` (login has it; generic modal does not).
- **1.3.1 / 4.1.2:** Heatmap relies on hover `data-tip`; weak for SR / keyboard. Token field is visually labeled; Soft still wants explicit `for`/`id` wiring audited.
- **2.5.5 Target size:** Product mobile nav/buttons aim at 44px; FAQ `[+]` chrome on LIVE is Soft-risk if only the glyph is the hit target.
- **Scanline overlay** (product `body::after`): always-on visual noise; vendor reduced-motion kills *animations*, not the static scanline — Soft leftover.

**Verdict: Soft pass REJECTED.**

## Ranked fixes (blocker / concern / note) + acceptance criteria

### Blockers

1. **Public GitHub / Star CTAs 404 (LIVE)**  
   - **AC:** Anonymous GET of every nav/hero/footer GitHub URL returns 200 to a real repository **or** CTAs are removed/relabeled (“Private preview — request access”) with no star affordance. Clone commands in Install match a resolvable repo.

2. **Soft nav unpaid — CORE + APPLY invisible in product WebUI**  
   - **AC:** Sidebar (and mobile pill nav) includes destinations that list **Job search**, **Application grill**, **Apply queue**, **Profile wizard**, **Doctor**, **Analytics** (or equivalent single “Core” route filtering those groups). Fresh-install user can launch Job search without knowing `cli.py`. Soft nav marked paid only when hash routes + labels ship.

### Concerns

3. **`--ink-faint` contrast Soft fail (~3.78:1)**  
   - **AC:** No UI text using `--ink-faint` (or darker) for readable copy on `--bg`/`--panel`; remeasure ≥4.5:1 for normal text / ≥3:1 for large. Soft leftover closed only after pass on LIVE + WebUI.

4. **LIVE demo dashboard vs product dashboard confusion**  
   - **AC:** `#/dashboard` (“WATCH THE MACHINE.”) visibly labeled as demo/seeded; copy points to `cli.py serve` for the real local dashboard; no implication that www.vetomcp.com hosts operator pipeline data.

5. **Hero motion without in-UI pause (LIVE)**  
   - **AC:** Visible pause/stop **or** static frame by default with “Play demo”; reduced-motion remains inert (already observed).

6. **CTA naming: START / TRY IT → install**  
   - **AC:** Primary header CTA label matches destination (e.g. Install / Get the MCP) **or** destination becomes a true start flow.

7. **Workflow modal missing accessible name**  
   - **AC:** `.modal` has `aria-labelledby` (or `aria-label`) matching the wizard title; axe/manual SR announces dialog name.

8. **30-day heatmap weakly labeled**  
   - **AC:** Visible legend + non-hover text alternative for cell meaning; keyboard focus can expose the same data as hover tips.

### Notes

9. **Phone guide radius drift** — Align `guide.html` to `--radius: 0` (retire `10px` / `999px` leftovers).  
10. **Scanline Soft leftover** — Document or disable under `prefers-reduced-motion` / user setting.  
11. **FAQ accordion hit area** — Entire row ≥44×44 CSS px.  
12. **Product brief craft** — Add a short UX brief stating primary path + LIVE/local split (no metrics invention).
